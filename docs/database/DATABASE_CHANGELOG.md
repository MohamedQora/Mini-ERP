# سجل التغييرات والتحقق

**الحالة:** الترحيلات الثمانية والاختبارات الستة اجتازت تشغيل Supabase محلي على PostgreSQL 17. إصدار 16 المستهدف غير متحقق.

## التغييرات في هذه المراجعة

- أضيف `08_security_rbac_and_app_compatibility.sql` كترحيل أمامي بدلاً من تعديل ملفات الأساس.
- أصبح محدد المستأجر من `app_metadata.tenant_id` الموقّع في JWT؛ لم يعد `app.current_tenant_id` كافياً لمنح الوصول.
- استبدلت سياسة العضوية العامة بقراءة محددة حسب صلاحيات الدور والمستأجر النشط، مع منع الكتابة المباشرة لجداول الأعمال.
- أضيفت رموز وأذونات أدوار ابتدائية، وحُجبت أسرار التكامل ودعوات المستخدمين وحقول التكلفة عن `authenticated`.
- أصبح المتاح من المخزون = الموجود − المحجوز − التالف. حجز المخزون يقفل مستوى المخزون، ويرفض إعادة المحاولة بكمية مختلفة، ويجعل إعادة المحاولة المطابقة بلا أثر إضافي.
- أصبحت جداول دفتر المخزون والتدقيق وحالات الطلب والشحن وتكلفة المتغير غير قابلة للتعديل أو الحذف عبر مشغلات.
- أصلحت مواءمة عميل الواجهة لأسماء حقول المستخدم/المستأجر، وأضيف دعم مفتاح Supabase publishable.
- أعدت كتابة الاختبارات لتطابق المخطط الحالي، وأضيفت سكربتات PowerShell لتشغيلها على Windows بأمان محلي.

## نتائج التشغيل

- `supabase db reset`: نجح على Supabase محلي باستخدام PostgreSQL 17 عبر متغير جلسة مؤقت لأن CLI يرفض الإعداد 16.
- مجموعات SQL `01`–`06`: نجحت بعد إعادة مواءمتها مع الجداول الموجودة.
- `npm run typecheck` و`npm run build`: نجحا قبل آخر تغييرات الواجهة؛ يعاد تشغيلهما في مراجعة الإنهاء.

## المخاطر المفتوحة

لم تُنفذ بعد دورة استلام المورد وWAC وخصم المخزون عند استلام شركة الشحن والمرتجعات والتسويات والربح. لم تُختبر المنافسة الحقيقية بين جلستين، أو صلاحيات المخازن، أو مصفوفة أدوار موسعة. لا يوجد تحقق PostgreSQL 16 أو اعتماد إنتاجي.

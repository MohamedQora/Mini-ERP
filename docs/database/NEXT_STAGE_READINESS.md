# المرحلة التالية للجاهزية

نجح bootstrap محلي واختبار SQL على PostgreSQL 17. لا يزال المشروع غير جاهز لتكامل الوحدات أو الإنتاج، وهدف PostgreSQL 16 لم يُتحقق منه.

## أدلة موجودة

- [x] تطبيق ملفات الترحيل الثمانية على قاعدة Supabase محلية نظيفة.
- [x] تشغيل مجموعات SQL الست.
- [x] تشغيل `npm run typecheck` و`npm run build` للواجهة.
- [x] اختبار RLS عملياً عبر دور `authenticated` لمستأجر واحد، بما يشمل محاولة تجاوز محدد المستأجر.

## عمل مطلوب قبل اعتماد القاعدة

- [ ] تشغيل نفس الترحيلات على Supabase/PostgreSQL 16؛ Supabase CLI الحالي في بيئة الفحص لا يدعم 16 محلياً.
- [ ] اختبار سباق حجز حقيقي بجلسات مستقلة، ثم سباقات الحجز/الإلغاء والتسليم الجزئي.
- [ ] تطبيق وفحص صلاحيات Warehouse-scoped للانتقاء والتنفيذ والشحن.
- [ ] استكمال RPCs لاستلام المورد، حساب WAC، خصم الكميات عند pickup، إعادة المخزون بعد الفحص، الإرجاع، التسويات، وإعادة حساب الربح.
- [ ] إضافة مصفوفة RBAC لكل دور ولكل عملية، وفحص دعوات المستخدمين وsupport grants.
- [ ] تشغيل فحوصات ترقية قاعدة سابقة ونسخ احتياطي/استرجاع.

## عمل مطلوب قبل اكتمال التطبيق

- [ ] ربط صفحات المنتجات والعملاء والطلبات والمخزون والشراء والشحن والمالية والتكاملات بعمليات آمنة.
- [ ] تنفيذ إنشاء الحساب/دعوة المستخدم ومسار إعداد أول مستأجر؛ الواجهة الحالية توفر تسجيل دخول واختيار مستأجر فقط.
- [ ] اختبار متصفح لتدفق تسجيل الدخول وتبديل المستأجر عند إعداد Supabase محلياً.
- [ ] إضافة سجل تدقيق من عمليات الخادم، ومصادر فعلية للإشعارات والبحث.

لا توصل أدوات الواجهة مباشرة بجداول الأعمال للكتابة. أنشئ RPC أو route خادمياً محدداً، مع تحقق الصلاحية وسجل تدقيق واختبار رجعي، ثم أضف سياسات الكتابة المناسبة.
